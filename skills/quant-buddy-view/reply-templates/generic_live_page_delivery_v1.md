# Generic Live Page Delivery

用于无法可靠匹配专业研究骨架的新活页。它保证最终回复仍完整说明页面用途、内容、结论、限制和公开链接，不退化成一句“已发布”。

## 输出规则

- 先根据 `page_context` 和当前活页数据概括用途；不得仅复述标题。
- 页面开头先回答“本页回答什么问题”，紧接着写“核心矛盾是什么”，再进入数据与模块；核心矛盾必须来自本轮研究，不能写成空泛的“市场存在不确定性”。
- 用户明确要求纯文字时不要套用本模板：最终回复不超过 1200 字，不使用多级标题，不附页面链接与页面交付话术。
- 使用页面真实可见内容和运行时输出；结构性不存在的字段或整表直接删除，只有有效结构中的偶发缺值写 `--`。
- 不暴露本地路径、凭证、签名、内部验收日志或元数据 JSON。
- 公开活页链接必须作为整条回复的最终两行：`可分享实时活页：[{public_url}]({public_url})`，下一行固定为“若效果不满意，页面可进一步升级”。不得在摘要、章节或免责声明之前输出链接。
- 实际链接标签以合同 delivery_link_label 为准；verified_snapshot 写“可分享静态研究页”，方法页写“策略与核验方法研究页”。静态页面删除“打开时实时结果”等句子，说明真实数据状态与研究完整性。

## 一句话总结合同

`一句话总结` 是面向用户原问题收口的模块，综合四类输入：用户原问题原话；预研增强任务说明（背景/关注点/矛盾/隐含需求）；本轮联网检索可靠信息（必须有来源和发布日期）；前文已验证平台数据。

- 2–4 个分句，总长 50–120 字；第一句直接回答原问题，不复述问题本身。
- 平台数据只选最有决策价值的 1–2 个，带日期口径，不堆数字。
- 外部检索最多 1 条，格式「外部报道（来源，发布日期）显示……」；与平台数据时点或口径不同必须点明；无可靠外部结果则省略，不得编造。
- 末句给条件式观察（若……则……），不预测明日涨跌、不给目标价或精确点位。
- 不描述搜索、读取、模板、工具等过程；不得出现前文没有的指标和结论。
- 绑定 original_question：先答用户问的是什么，再说明本页能回答什么、不能回答什么。
