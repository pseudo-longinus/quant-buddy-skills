# 自建活页的结构与交付底线

在 `unmatched` 自建分支生成页面前读取。**本轮整页必须由模型手写 HTML/CSS/JS**；`build_dashboard` 不得生成 `research-v1` 标准整页替代 bespoke 自建页。已有自有页、用户提供的 HTML 和 fork 继承页继续保留原布局，不要借本规则强制重做。

## 先组织回答，再设计页面

先确定用户要判断什么、哪组已验证数据支持判断、首要证据是什么、阅读顺序是什么。不要先想卡片网格，也不要把运行时 output key 当作栏目标题。

| 主要任务 | 首要证据 | 默认阅读顺序 |
|---|---|---|
| 关键价位、估值位置 | 有日期和单位的关键值；有序列时才画趋势 | 标题与研究范围 → 关键值/主图 → 条件解释 → 口径与边界 |
| 名单、排名、横截面对照 | 带名称、排序字段、单位的可读表格或条形图 | 标题与筛选定义 → 排名/对照 → 差异解释 → 数据范围 |
| 趋势、收益、回撤 | 同口径、同窗口的主图 | 标题与观察问题 → 主图 → 关键变化 → 解读与口径 |
| 事件、研究报告 | 证据时间线、明确的条件或分段结论 | 标题与核心问题 → 证据主体 → 条件分析 → 来源与边界 |

设计底线：

- 首屏出现主题、范围、核心结论和真实关键证据；不要用长篇导语把主图或榜单推到后屏。
- 桌面与手机首屏都要可读；320px 不留横向滚动。
- 核心数字用大字号和明确颜色层级，辅助口径弱化。
- 图文交替：标题 → 结论 → 图表 → 白话解读，避免连续表格或等权卡片堆叠。
- 每张图写 1–2 句“怎么读”；没有序列就不要伪造曲线。
- 缺失值、数据日期、单位、实时/快照边界必须可见。
- 不得把 output key、请求参数或内部路径当成读者可见标题。

## 模型手写生成路径

1. 按 [bespoke 页指南](bespoke-page.md) 直接写完整主体 HTML/CSS/JS。
2. 数据层使用公共 data-kernel：Formula Package 用 `QB.query` 与 `QB.series/lastValue/topValues`，Data Grant 按 `QB.snapshotRows` 解包。
3. 公共 shell / logo / QR / data-kernel 通过 `python scripts/compile_bespoke_page.py @params.json` 内联，页面自包含。
4. 如需声明式图表，只能调用 `build_dashboard.py` 且显式 `emit:"panel_block"`，把返回脚本嵌入模型手写的容器；外层布局、间距、配色、叙事仍由模型控制。
5. 主体根节点声明：
   ```html
   <main data-qb-page-design="bespoke-v1" data-qb-delivery-kind="result">
   ```
   模块标题、正文和关键数值分别声明 `data-qb-module-title`、`data-qb-prose`、`data-qb-metric`，供浏览器质量检查定位。
6. 手写图表必须处理取数失败、空值、日期缩放和轴单位；价格序列处理假 0 时使用 `{dropZero:true}`，涨跌幅/收益率的 0 必须保留。
7. 不确定如何排版时，优先设计一个能回答用户问题的首屏，而不是退回标准卡片网格。

## 浏览器与发布验收

1. 本地运行：
   ```bash
   node scripts/verify_page.mjs <html_file> --require-browser --expected-title "最终主标题"
   ```
   覆盖桌面、390px、320px，并检查标题、正文、表格、图表与横向溢出。
2. 查看三个视口实际截图：核心证据是否快速可辨、是否有大块空白、图表标签是否可读、缺失态是否明确。自动检查不能替代截图审查。
3. 取数成功、存在 H1、无 JS 报错都不足以单独证明可交付。
4. `publish_verified` 必须传真实研究内容的 `description`、当前 `task_id/page_id/plan_hash`、候选 `html_file`、标题、实时/快照合同与验证收据；缺 `page_id/html_file/description` 是参数缺项，补齐后重发，不执行恢复降级。
5. 发布后继续执行同页公网验收与终态回复合同；公开页内容必须与最终回复链接一致。

## 排名与比较语义

- 排名必须保留原始带符号收益，不得把最弱榜取反成“跌幅大小”。
- 完整截面、筛选口径、观察日与名次定义必须写清。
- 多资产对比优先用透视结构：指标为行、资产为列；不要把 API 长表原样丢给用户。
- 最强/最弱榜来自同一完整截面和同一观察日。
- 未核验更新频率时，只写“刷新代表重新请求”，不承诺上游已完成当日更新。

不能完成浏览器或视觉验收时，按任务失败/恢复流程收尾，不把简陋骨架当最终页交付。
