# 连续期货：换月、价格尺度与局部数据差异

使用国内期货主连/次主连做跨日、跨频、指标、回测或活页时读取。主力如 `A.DCE`，次主力如 `A_S.DCE`。先确认字段口径，再完成用户任务；局部缺失与跨频差异按下述影响范围处理。

## 新版换月事件

`fast_query` 的 `future_context[ticker].roll_events` 和单资产 `fast_query_minute_range` 的 `roll_events` 保留服务端返回的 `columns + data`。新版列为：

```json
["decision_trade_date", "effective_trade_date", "old_contract", "new_contract", "old_close", "new_close"]
```

| 字段 | 含义 |
|---|---|
| `decision_trade_date` | 换月决策交易日，当日盘后确定换月；也是两条参考收盘价的实际取价交易日 |
| `effective_trade_date` | 下一交易日，换月生效日；从归属于此交易日的首根bar开始切换到新合约，直到后续换月再次切换 |
| `old_contract` / `new_contract` | 换月前后两条具体合约 |
| `old_close` / `new_close` | **决策日**旧、新合约各自的原始日频收盘价，未复权；不是生效日收盘，也不是分钟换仓成交价 |

事件窗口按 `effective_trade_date` 过滤，因此首条事件的决策日可以早于窗口起点。夜盘按行情 `trade_date` 归属，有夜盘的品种可从前一自然日晚间开始生效；不能按UTC或本地自然日截断。

按 `columns` 建立列名到索引的映射，不硬编码五列或固定位置，不把新字段改名、合并或丢弃。旧版五列事件中的 `trade_date` 表示生效日，可在内部作为 `effective_trade_date` 的兼容别名；旧版未返回决策日时，不用自然日减一伪造取价日。行情行及 `contract_info.contracts[].trade_date` 仍表示行情所属交易日，不应一律改名为决策日。

单日 `fast_query_minute` 仍只提供所选交易日和简洁 `contract_info`，不期待它返回事件表。多资产分钟未返回换月元信息时不假定事件存在或为空；仅在目标计算确需时使用已支持的事件入口补充，不为普通行情展示额外扩查。`inferred` 是事件推导，不表示独立实时核验。

## 价格尺度和复权算法

日频 `results` 的连续价格字段为已复权价格；显式 `收盘价（不复权）` 为原始价格。分钟OHLC保留原始未复权报价，事件中的两个close也未复权。比较前必须统一尺度，不能仅因复权日价与原始分钟/参考价不相等就判定数据错误。

例如生效日2025-11-13、决策日2025-11-12，`old_close=945.76`、`new_close=948.74`：这两个数均为11月12日各自合约的原始收盘，价差为2.98；它们不要求等于11月13日的日频收盘。不能仅凭数值相等或不同推断另一个字段是否复权，应以实际请求字段为准。

分钟连续参考序列按本换月接口的**加法价差**构造。对事件i设 `jump_i = new_close_i - old_close_i`，事件按生效日排序，bar所属交易日为t：

- 后复权，锚定最早段：`P_back(t) = P_raw(t) - sum(jump_i where effective_trade_date_i <= t)`。
- 前复权，锚定最新段：`P_front(t) = P_raw(t) + sum(jump_i where effective_trade_date_i > t)`。

保留原始OHLC，另生成派生参考OHLC并标注锚点、事件覆盖窗口和算法；不覆盖原报价、不重复复权、不改成交量、不默认改用新旧价比。前复权的最新段锚点以已取得的完整目标事件窗口为准；全历史后复权需覆盖起点之前所需的事件，不能把窗口内事件当完整历史链。

上述公式是原始分钟的参考序列算法；复现日频 `results` 仍需匹配其具体复权方向、锚点和事件范围，不能未经核实就承诺完全相等。跨尺度的止损、目标和历史低点须做相同平移；ATR等价差指标在统一后的序列上计算，不把加法偏移直接加到ATR上。

换月日新开新平且未跨合约边界的交易可正常分析，不整日排除。跨月参考变化可以研究，真实账户损益需具体换仓报价、手数和成本；日频参考价不能冒充分钟成交价。历史参考重放可继续完成；实时信号仅在所用信息当时已可得时成立，决策日字段不是精确的首次发布时间。

## 日分钟对账的适用范围

- 正常构建的日线OHLC来自当天同一来源合约的统一口径，不是open用旧合约、close用新合约的混合拼接。
- 日线可能直接取供应商日线，也可能由原始分钟聚合；日频与分钟频来源/构建流程可能不同，不承诺等于当前对外连续分钟的重聚合结果。
- 日量等于分钟量之和，只在同来源口径、同实际合约、同交易日完整时段、无缺失/重复、单位及单/双边统计一致、版本一致时作为相等校验。条件未确认时，差异是待解释项，不直接判错。
- 当前代码直接传递供应商volume，未统一做单/双边除二转换；全部历史来源的单双边口径尚未独立核验。少数日期数值一致不能扩大为全历史保证。

## 局部问题默认非阻断

发现少量分钟缺失、端点差异、日分钟价格或量不齐时，记录受影响的日期、字段和计算路径，继续完成可用部分、首答和页面交付。不得自行把“跨频严格相等”加成用户任务的全局门禁，不因此删除全年数据、整段窗口或无限重查，也不必等待厂商答复才能继续不受影响的分析。

按任务依赖处理，而非按缺失条数一刀切：

| 情况 | 处理 |
|---|---|
| 量不齐，但任务只分析价格趋势 | 保留价格分析，披露量的来源差异；不阻断 |
| 个别分钟缺尾，日线来自独立有效日频结果 | 日频分析继续；分钟图标出缺口，不用最后现存分钟冒充正式日收盘 |
| 缺失bar恰好影响止损/目标是否先触发 | 仅该笔交易路径/收益标未知，继续其他可验证交易，并报告有效/未知数量 |
| 换月元信息缺失，原始行情已成功 | 继续原始行情展示和不跨接缝的分析；依赖缺失事件的映射/跨月路径标未知，不假定无换月 |
| 所有核心输入都不可用，目标结果确实无法计算 | 明确说明无法完成的部分，并交付仍可完成的内容 |

原始缺口、null和端点行保留；不补0、不删端点凑量、不把缺失收益当0、不静默改策略参数或请求窗口。页面和回答简要披露有效范围、缺失及其实际影响，不把一般告警写成“整年数据不合格”或“任务失败”。
