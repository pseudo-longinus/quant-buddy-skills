# 分钟行情支持市场与历史起点

适用于 `fast_query_minute`、`fast_query_minute_range`、`fast_query_minute_range_multi` 及对应 Data Grant。来源：用户提供的上游文档《000000-分钟数据.md》，于 **2026-09-15** 对齐；下表是本平台覆盖范围，不是交易所成立日、资产上市日或全市场分钟数据通用历史。

## 已确认覆盖表

| 资产类型 | 中国市场 | 美国市场 | 香港市场 |
|---|---|---|---|
| 股票行情 | 2026-05-13 | 2026-05-13 | 2026-05-20 |
| 指数行情 | 2026-08-13 | 暂不支持 | 暂不支持 |
| 期货行情 | 2005-01-04 | CME Group外盘主力连续：见下方逐ticker表 | 暂不支持 |

起始日期包含当日，按行情所属的 **交易日 `trade_date`** 比较，不能用 UTC 时间戳对应的自然日判断。夜盘也按交易日归属判断。

除外盘期货须使用下方逐ticker起点外，这是**市场 × 资产类型的最早覆盖边界**，不保证每个资产当天已上市/挂牌、有成交或数据齐全。单个股票、指数、具体期货合约实际首条数据可能更晚；最终以接口返回为准。国内主连/次主连与外盘主力连续均按各自覆盖规则，不因附带换月事件而获得更早的分钟行情。换月事件历史与分钟行情历史不是同一范围。

## 调用前必须判断并提示

1. 先用资产库确认唯一资产、市场和资产类型；不能仅凭名称或“日频能查到”推断分钟频支持。表中未列明的类别（例如基金/ETF、其他市场）视为**覆盖待确认**，不要自行套用股票起点或断言不支持。
2. 对历史请求比较用户窗口与对应起点；offset 先按**资产市场当地日期**折算为自然日窗口，不能一律按北京时间，也不能当成交易日偏移。起点包含当日；本规则不放宽历史工具“不得含市场今天/未来”、单次三个日历月和 offset `[-70,-1]` 的限制。
3. **全窗口早于起点**（`end_date < 最早日期`）：调用前直接说明该类别最早日期，以及本次区间无可提供的分钟行情；不进行明知越界的查询、不为此注册授权、不空转重试。可建议从支持起点重新选择区间，但不能未经说明改查别的日期，也不能用日频数据冒充分钟数据。
4. **部分窗口早于起点**（`start_date < 最早日期 <= end_date`）：先提示缺失区间，说明只能提供支持范围内的数据。在满足原有日期限制时，可继续查询原窗口内可用部分；保留用户原始窗口，不静默改参。答复/导出说明/页面标注同时展示“请求区间、平台覆盖起点、实际返回范围”，不得声称已覆盖完整请求。若用户要求完整覆盖，先说明无法满足并让用户选择可用范围，不交付部分结果冒充完整结果。
5. **在覆盖范围内**：正常查询，但空结果不能直接认定为未到支持起点，可能是休市、未上市/挂牌或该资产数据缺失；也不能把某次查询的第一条数据说成该资产有史以来最早数据。
6. **明确暂不支持的组合**：调用前提示“本平台暂不支持该市场该类资产的分钟行情”；不尝试用另一个分钟工具绕过。此限制不代表该资产的日频行情也不支持。

## 数据授权与活页

注册、Fork 改资产、修改授权窗口前同样检查。授权保留原始日期或 offset 语义；不为凑出非空数据而静默裁剪 payload、替换市场/资产或将 offset 固定为绝对日期。整个窗口越界或明确不支持时，不创建声称能动态取数的授权；仍可按用户需求交付带清晰数据限制说明的静态内容。

部分覆盖页面要标注数据起点与实际返回范围，不补零、不伪造更早数据，不把 `is_live:true` 当成完整覆盖或实时盘中行情保证。动态 offset 窗口每次取数会滚动，实际数据范围不能写死为构建当天的范围。

## 提示示例

- 国内期货，请求 2004-12-01 至 2005-01-31：“国内期货分钟行情最早从 **2005-01-04** 开始提供。您请求的 2004-12-01 至 2005-01-03 超出覆盖范围；本次只能提供 2005-01-04 至 2005-01-31 内实际存在的数据，无法完整覆盖原区间。”
- 国内指数，请求 2026-07-01 至 2026-07-31：“国内指数分钟行情最早从 **2026-08-13** 开始提供，所选区间全部早于支持起点，当前无法提供该区间的分钟行情。”
- 香港指数：“本平台暂不支持香港指数分钟行情；不能用港股股票的分钟数据覆盖范围代替。若需要日频行情，可另行确认需求。”

## 服务端返回合同（需部署对应后端版本）

`fast_query_minute_range` 及对应 Data Grant 已补服务端护栏，不再只依赖 skill 提示：

- 全窗口越界：HTTP 400，`error.code=MINUTE_HISTORY_OUT_OF_RANGE`，错误中有 `earliest_available_date`、`requested_start_date/requested_end_date`、`market/asset_type`、`retryable:false`。解释该边界，不将其当成成功空 CSV，也不原参数重试。
- 部分覆盖：行情成功仍HTTP 200；`data.warnings[]` 包含 `MINUTE_HISTORY_PARTIAL_COVERAGE`，`data.coverage` 给出类别起点、原请求范围、`partial:true` 和 `unavailable_range`。保留提示，不能因CSV非空就宣称完整覆盖；`coverage`不是实际首条/末条日期。支持范围内 `coverage.partial=false`，仍可能合法返回空数据。
- 授权注册/刷新同样校验，存量越界授权查询也报错；部分覆盖注册/刷新成功时 `coverage/warnings` 在顶层，查询成功时在 `data` 内。不要把这些响应字段写入冻结payload。
- 历史覆盖警告可与换月警告同时出现，两者都要保留。旧服务若仍成功返回越界空CSV，按本表提示并说明后端版本待更新，不认为旧行为代表扩大覆盖范围。

上游覆盖范围后续变更时，应重新核对并同步本表，不能仅因时间过去就推定历史已自动补齐。

交易日按`America/Chicago`会话归属，本地17:00起进入下一会话日，周末顺延；上游默认日期规则不跳过节假日，不等同于精确节假日/提前收盘日历。使用IANA时区处理夏冬令时，不写固定北京时间偏移。分钟过滤的`timezone`仅控制日内时钟，不改变`trade_date`归属；没有分钟过滤时不必额外添加timezone参数。

三个已有请求合同不变：

- 当前/最近完整日：`fast_query_minute({"asset":"ES.CME","fields":["close","volume"]})`，不添加trade_date/timezone等未开放参数。
- 单资产历史：`fast_query_minute_range({"asset":"TU.CBT","start_date":"2021-12-01","end_date":"2021-12-10"})`，全列CSV，不传fields/format；日期上限和自然日offset逻辑不变。
- 多资产历史/时段：`fast_query_minute_range_multi({"assets":["ES.CME","TU.CBT"],"start_date":"2021-11-01","end_date":"2021-12-10","start_minute":"08:30","end_minute":"15:00","timezone":"America/Chicago"})`。仍用assets/asset/market三选一，不传内部tickers或format/fields；查询全市场可换成`market:"os_future"`。
- 外盘跨零点窗口支持`17:00`至`02:30`并显式`timezone:"America/Chicago"`；跨市场资产共用一个过滤时钟，自动日期跨日历域仍按原规则拆分。

单资产全部早于自身起点：解释MINUTE_HISTORY_OUT_OF_RANGE，不调用或注册明知越界的授权；部分重叠：保留原窗口、原始缺口及MINUTE_HISTORY_PARTIAL_COVERAGE警告，不补0、不改查别的日期。多资产按各自起点提示并保留可用资产数据，不把全体起点取最大值后静默裁剪。例如ES+TU查2021年11月至12月，ES保留11月数据，TU提示2021-12-01之前不覆盖；全部所选资产已知越界才整体拒绝。接口返回coverage/coverage_by_ticker时保留其语义，不把起点字段当作实际首条记录或完整性保证。market模式以窗口内实际有数据的资产为准，不硬编码成上述13个ticker请求。

本次外盘接入支持原始主力连续分钟行情，不新增外盘具体合约映射或换月事件附加能力；未返回contract_info/roll_events时不伪造，也不据此否定成功行情，价格仍不复权。

QBV沿用三个同名Grant及既有验证、注册、刷新、计费流程；payload只含请求字段，不放coverage/warnings。绝对窗口固定，rolling/offset按原规则滚动。页面按ticker分组，展示实际数据日期、请求窗口和覆盖限制；空数据不冒充0价格，历史数据不标成当前盘中。此更新依赖配套skill_server及上游任务部署，不代表当前运行服务已自动更新。
