# stock-profile · 单股指标画像

> **适用范围**：用户要求“分析一下 XX 个股”“看一下 XX 这只股票”“个股画像”“指标概览”“估值财务资金走势综合看一下”等开放式单股综合指标概览。
> 本 workflow 使用 `stockProfile` 单次调用完成，不使用 `fast_query` / `runMultiFormulaBatchStream` / `readData` 拼接画像，不使用 `scanDimensions` 做 IC 扫描。

---

## 路由边界

若原话是单个资产名称/简称/代码，或“分析一下/全面分析/个股画像”加单只 A 股，先执行 `live_page_routing.py route`。命中 `single_a_stock_fast` 时保留默认建页意图，按 `live-page-routing.md` 的裸 A 股入口先答后建页；不得将其降为一次性画像问答。

| 用户意图 | 路由 |
|---|---|
| 最新价、今日涨跌幅、PE、PB、市值、ROE、营收等单字段或少量字段 | `fast_query` 对应 workflow |
| 最近 N 日走势、窗口最高/最低、区间涨跌幅序列 | `fast_query` 对应 workflow |
| 单股指标画像、全维度概览、综合看估值/财务/资金/走势 | 本 workflow |
| IC、预测力、哪个维度有效、维度打分 | `scanDimensions` 相关路径 |
| 多股票横向比较、选股、回测、自定义公式 | `quant-standard.md` 或对应 workflow |
| 能不能买、后期怎么看、目标价 | 本 workflow 可先给指标画像，但必须拒绝投资建议和价格预测 |

## 执行步骤（严格顺序）

```
① 提取单个 asset 和用户关注维度
→ ② 调用 newSession（若本轮尚未显式调用；调用 stockProfile 前不可省略）
→ ③ 对 asset 执行 grep presets/assets_db/{stock_a,stock_hk,stock_us}.yaml 查本地库
     - 命中唯一 → 优先使用标准名称或代码传参
     - 命中多条 → 向用户澄清，禁止继续查数
     - 未命中 → 保留原始 asset，由 stockProfile 服务端兜底解析
→ ④ 调用 stockProfile
→ ⑤ 按返回 dimensions 输出完整个股分析（明确要求简短时才精简）
```

调用参数模板：

```json
{
  "asset": "贵州茅台",
  "user_query": "<用户的原始问题>"
}
```

`task_id` 由调用层自动注入，不要手写伪造。

**取数停止条件**：`stockProfile` 返回 `code: 0` 且 `data.indicators_count > 0` → 直接基于 `dimensions` 输出，不再调用 `fast_query`、`scanDimensions` 或公式链。无建页意图时可结束；裸 A 股快页或已有建页意图时，此输出是非终止业务首答，随后同轮继续 QBV，不询问用户是否还要展开来替代已确定的页面交付。

## 输出结构

裸个股、个股画像及“分析一下/全面分析”默认使用下面的完整结构。是否建页只改变后续交付，不降低文本分析深度。用户明确只要简短概览、某个维度或单个字段时按其范围回答，不强塞完整模板。

标题为“{资产名称与代码}分析”；时间说明使用实际字段日期，不用接口计算时间冒充行情日期。先给一段有数据依据的核心判断，再按以下顺序展开：

| 章节 | 有数据时必须覆盖的核心内容 |
|---|---|
| 一、行情与估值 | 价格、20/60/120/250 日收益；PE/PB/PS、股息率及各自已返回的 1/3/5 年分位 |
| 二、财务分析 | 毛利率、净利率、营业利润率、收入与扣非增速、ROE/ROIC、经营现金流；合同负债、资本开支（含资本开支/收入）、在建工程，以及返回的原始营收、归母净利润和资产负债率 |
| 三、资金 / 交易特征 | 基金持仓、成交额占比、换手、卖空等已返回指标及趋势/分位 |
| 四、计算维度 | 相对强度、形态、趋势、动量、量能、情绪、异动等动态评分，说明评分量纲；财务质量评分与原始财务值分开 |
| 五、波动率与风险 | 年化波动率、标准差及各自历史分位；结合前面数据说明可核验的风险，不从分位反推未返回的波动率值 |
| 六、综合观察 | 回答用户目的，结合估值、盈利、增长/现金流、交易与风险形成有证据的判断，指出矛盾和观察条件，不只重复数值 |

数据章节默认用“指标｜可核验数据（含单位、口径）｜数据日期”的表格。核心指标的可用单季、同比/环比、TTM、年度、上一有效值或历史分位在同一行或分组展开，不能固定每维度只取 2～4 项；不要求堆出全部 233 个扩展指标。渠道限制表格数时转为分组列表，但保留核心内容。其他已返回维度按用户关注点补充，禁止把它们硬套为上表中的金融量。

`stockProfile` 的 `data.answer_financial_table` 是脚本从本轮画像直接整理的财务表，不新增查询。综合分析时第二章直接使用其 `markdown` 并附 `notes`，不得挑选删行、删变体或改写数值；`field_refs` 只作内部覆盖核对，不向用户展示。旧响应没有该字段时才按下述规则整理。明确只问少数字段或简短概览不强制整表。

完整财务行按同一检查表整理：最新值与日期 → 单季同比/环比 → TTM 及其同比 → 年度及其同比；仅列实际返回且适用的口径，上一有效值作为比较补充，不能替代同比/环比。不要只给部分指标在表后补一个混杂的“变动率”段落，导致其余核心指标的已返回口径被省掉。收入增速等增长率指标自身的同比/环比是“增速的相对变化”，不能当成营收同比或百分点变化。

排版示例（变量只从返回值填入，无值省略，不照抄占位符）：

```text
| 毛利率 | 单季 {值}%；同比 {值}%；环比 {值}%；TTM {值}%；TTM 同比 {值}%；年度 {值}%；年度同比 {值}% | 单季/TTM {日期}；年度 {日期} |
```

日期相同的口径合并标注（如“单季/TTM 2026-06-30；年度 2025-12-31”），仍能逐项追溯，不能把不同日期写成同日。计算维度不逐项解释全部子分，保留维度总分和最相关差异；结尾只提炼两到三条有依据的观察。

前五章每章最多一张数据表；财务变体合并到对应指标行，不再按单季、年度和变动率拆出多套表。计算维度以各维度总分为主，每行最多补两项与用户目的相关的细分评分；没有总分则注明，不用细项冒充总分。财务核心原值的覆盖优先于扩展评分清单，禁止为罗列几十个评分而漏掉已返回的资本开支单季值等核心事实。单位未核验时保留原值并标注，不能把 trend60 原值无依据乘以 100。

整章缺失时保留标题并写“本轮未返回可核验的该章节数据”；章内未返回的指标不编造，用户明确要求却缺失的字段单独说明。没有这些数据时不标榜“全面覆盖”。

读取规则（响应已压缩）：

- `latest_date` 和 `unit` 可能在维度层级而非指标层级——先查维度，再查指标自身，取最具体的。
- 数值已由服务端按精度 round，直接展示即可。
- `unit` 为空时不强加单位。变体自身的单位和日期优先于父指标、维度；金额指标的同比/环比不能机械继承“元”，单位或缩放未核验就明确标注，不能猜测转换。
- `latest_value` 或 `previous_value` 为 null / 缺失时，只输出可用字段；缺少 `previous_*` 表示本轮没有可用历史，不得写成 0，也不要再用 `fast_query` 或公式链补算。
- `previous_value` 按自身 `previous_date` 展示，不把上一有效值的日期覆盖为本期。预计算指标的 `previous_*` 是上一期；千维动态数值指标的 `previous_*` 是严格早于 `latest_date` 的上一有效值；千维布尔指标则表示上一次命中。
- `latest_date` 是 `YYYYMMDD` 数字，可展示为原值；不要自行改成报告期描述，除非字段语义明确。
- `variants` 是同一指标的不同口径（如 `quarter_yoy`、`ttm_level`、`pctrank:1Y`）。完整分析按上表保留核心指标的已返回口径；只有用户缩小范围时才选择性精简。变体的 `date` / `pre_date` 仅在与父指标不同时出现，缺失则继承父指标的日期。上一期值不等于同比/环比，评分不等于利润金额或财务比率；禁止混写。

## 空数据和错误处理

| 情况 | 处理 |
|---|---|
| `ASSET_NOT_FOUND` 且本地资产库未命中 | 说明“无法识别资产：{asset}”，不得替换为相似股票 |
| `ASSET_NOT_FOUND` 且本地资产库已命中 | 标记 `asset_catalog_conflict`，读取 `external-fact-verification.md` 核验上市/更名/换代码等事实；不得推导为公司未上市。外部事实确认但平台仍无数据时，说明“Quant Buddy 平台数据当前不可用” |
| `indicators_count = 0` | 说明该资产暂无预计算指标数据 |
| `warnings` 存在 | 原样吸收为口径提示，简明告知用户 |
| 某维度为空 | 完整分析对应章节说明未返回，不说“异常”；用户限定范围时不额外扩章 |
| 港股/美股部分维度缺失 | 说明“本轮接口未返回该维度指标”，不推断为公司没有该指标 |
| HTTP 429/503 | 按全局 429/503 规则处理 |
| HTTP 500 / 网络错误 | 标记 `quant_buddy_data_status=blocked` 并受控失败；外部搜索不得掩盖系统错误或补写平台数据 |

## 最终回答合同

首句必须是数据结论，例如：

```text
{资产}的估值分位为{已验证事实}；盈利与现金流呈现{有数据支持的状态}。以下按各字段实际日期展开。
```

随后交付上述六章。核心判断及综合观察要解释数据之间的关系：例如负 PE 不直接解释为便宜、营收增长不等于利润改善、利润与经营现金流是否同向；只在本轮证据支持时使用这些判断，不预设结论。不要用“返回 N 项指标”或计算耗时代替业务结论，也不要用“需要进一步展开吗”代替默认应交付的分析。

有建页意图时，这份完整分析就是非终止首答，不能因为随后有活页而缩成摘要，也不提前放页面链接。随后按 QBV 回复合同收尾：完整非终止首答真实可见后，快页传 `reply_mode:"page_followup"`，验收后仅补简短页面说明和链接；宿主不能中途显示首答时保留默认完整终态模板。不得自行删改工具返回的草稿。明确不要网页只取消建页，不取消分析内容。

综合观察前核对（在本次回答生成内完成，不新增模型或数据调用）：

- 每条观察的小标题、首句、证据和结论必须一致。例如正文写“净利率与现金流同为负”，标题不能写“利润与现金流不同向”；必须按同一期间区分水平正负与同比/环比方向，不拿单季正值与 TTM 负值混写“利润转负”。无法明确比较口径时只列事实，不用同向/背离标题。
- 不从风险聚合分倒推“多项信号未同时命中”等计算过程；只可引用已返回的指标定义和子项数值。总分小且子项非零时分别报告，不能替用户排除风险。

- 风险总分较低不能推出“未见风险/没有爆雷信号/财务安全”；除非字段明确定义阈值且所有相关证据支持，否则只报具体分数和方向。风险子项与总分背离时分别说明，不用总分抹去非零子项，不自造高低阈值。
- 不同维度的分数不能直接相减或比较后推出“相对强度好于绝对走势”“现金流质量优于盈利能力”等结论；成交额占比和换手评分不能单独证明拥挤度、恐慌或资金态度。无明确阈值时用具体数值或本维度历史分位描述，不自行定义强弱等级。
- 评分的范围、方向和“高分更好/风险更高”按各自 `description` 解释，不统一宣称所有评分越高越好，也不假定只有个股情绪可为负。只有字段说明明确正负对应方向时才作方向判断。
- 区间收益逐个写明窗口；20 日负收益、60 日正收益只能说明不同区间表现不同，不能直接推出“最近正在反弹”、拐点或持续走势。
- 零值按接口语义解释，不统一当成无数据或风险为零；未返回不能填零。观察清单聚焦少数最相关条件，不把每个分数都扩展成结论。

如果用户问“能买吗 / 后期怎么看 / 目标价多少”：

```text
本工具返回的是预计算指标画像，不能据此给出买卖建议、目标价或价格预测；可基于已返回指标说明当前估值、财务、资金和走势的事实状态。
```

## 保护规则

1. **evidence-only**：只输出 `stockProfile` 返回支持的指标、日期和口径。
2. **不补字段**：接口未返回的指标不得用模型常识、外部网页或其他工具补写。
3. **不抢简单查数**：用户只问单字段或明确窗口时，回到 `fast_query` 路由。
4. **不做 IC 扫描**：用户要求预测力、IC_IR、维度打分时，转向 `scanDimensions`，不要用 `stockProfile` 代替。
5. **不做投资建议**：禁止直接回答“买/卖/持有”、目标价、确定性涨跌判断。
6. **不泄露过程**：最终答案不出现 workflow、工具调用过程、内部路径。
